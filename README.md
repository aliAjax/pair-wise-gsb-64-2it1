# 食品工厂HACCP控制计划与偏差处置平台

独立React前端工程，采用Fluent UI、Redux Toolkit、React Router、Vite和TypeScript。数据通过浏览器持久化，无需后端。

## 统一生效依据（控制矩阵版本）

控制矩阵、批次监测、偏差处置、放行结论共用同一份生效依据，规则收口在 `src/services/basis.ts`：

- 控制矩阵按**版本发布**并带生效时间（数值化关键限值，可计算）。
- **批次投产即固定矩阵版本**（`batch.matrixVersionId`），之后矩阵改版不改变该批次的判定——旧批次不会被新限值放行/拦截。
- **矩阵更新后，固定到新版的未签字批次立即重算**结论（实时判定 + `recalculatedAt` 标记）。
- **已签字批次冻结**：结论行、矩阵版本、签字人、终端随签字快照保存，之后只读展示，补录读数也不重算、不开偏差。
- 放行结论按固定版本逐控制点判定（缺读数/最新超限/未关闭偏差/关闭未确认均阻塞）。

## 监测补录与偏差处置

- 超限（在线或补录）读数**自动开偏差并冻结放行**，偏差记录开偏差时的矩阵版本与限值文本。
- 重复补传按 `clientId` **幂等去重**，不重复落库、不重复开偏差；同控制点后续超限归集到未关闭偏差。
- **已关闭偏差不会被补录重新挑起**：关闭后再来超限只开新偏差。
- 偏差复核关闭后，还需**同一控制点、关闭时间之后的合格读数**确认，放行才解除冻结。

## 并发与可靠性

- **两台终端同时提交同一批次结论时先到者生效**：以 `conclusionSeq` 做乐观并发，后到者提交被拒，填值（签字人/备注）保留为本机草稿并看到冲突横幅；可基于新版本重新提交。多标签页通过 `storage` 事件同步对方已生效状态。
- **本地写入失败**（顶部开关模拟）后，监测点进入本机恢复队列（outbox），一键"补传未完成监测点"恢复；补传走同一幂等通道。
- 本机终端身份/草稿/队列存 sessionStorage，共享业务数据存 localStorage。

## 页面

- 生产批次：批次固定依据、逐控制点结论行、读数录入/补录、outbox 恢复、结论提交/签字冲突。
- HACCP控制矩阵：版本列表、按版本查看、基于当前版本改版并发布（触发未签字结论重算）。
- 偏差调查：调查/复核/关闭、固定依据展示、关闭后的合格确认状态。
- 追溯审计：矩阵发布、自动开偏差、结论冲突、签字冻结等全事件审计。
